# 1. PROJECT PROBLEM STATEMENT

A telecom company stores daily customer usage information in a MySQL database.

Every day, the company wants to process:

* Call minutes
* SMS count
* Mobile data usage
* Customer plan
* Telecom circle

The company wants to automatically:

1. Extract MySQL data using Sqoop.
2. Store raw data in HDFS.
3. Wait for confirmation that the daily data is ready.
4. Validate the ready condition.
5. Transform data using Hive.
6. Generate customer usage summaries.
7. Schedule the entire pipeline using Airflow.
8. Retry failed tasks.
9. Monitor the pipeline from Airflow UI.

# PART 21 — CREATE HIVE TRANSFORMATION SCRIPT

Create:

```bash
nano ~/telecom-etl/scripts/telecom_transform.sql
```

Enter:

```sql
CREATE DATABASE IF NOT EXISTS telecom_dw;

DROP TABLE IF EXISTS telecom_dw.customer_usage_raw;

CREATE EXTERNAL TABLE telecom_dw.customer_usage_raw (
    usage_id INT,
    customer_id STRING,
    plan STRING,
    call_minutes INT,
    sms_count INT,
    data_gb DECIMAL(10,2),
    usage_date DATE,
    circle STRING
)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ','
STORED AS TEXTFILE
LOCATION '/telecom/raw/customer_usage';

DROP TABLE IF EXISTS telecom_dw.customer_usage_fact;

CREATE TABLE telecom_dw.customer_usage_fact AS
SELECT
    usage_id,
    customer_id,
    UPPER(plan) AS plan,
    call_minutes,
    sms_count,
    data_gb,
    call_minutes * 1.0 AS call_usage_score,
    usage_date,
    UPPER(circle) AS circle
FROM telecom_dw.customer_usage_raw
WHERE call_minutes >= 0
  AND sms_count >= 0
  AND data_gb >= 0;

DROP TABLE IF EXISTS telecom_dw.customer_usage_summary;

CREATE TABLE telecom_dw.customer_usage_summary AS
SELECT
    customer_id,
    MAX(plan) AS plan,
    SUM(call_minutes) AS total_call_minutes,
    SUM(sms_count) AS total_sms,
    SUM(data_gb) AS total_data_gb
FROM telecom_dw.customer_usage_fact
GROUP BY customer_id;
```

Save.

# PART 34 — CREATE THE COMPLETE DAG

Create:

```bash
nano ~/airflow/dags/telecom_customer_usage_etl.py
```

Paste:

```python
from datetime import datetime, timedelta
import os

from airflow.sdk import DAG

from airflow.providers.standard.operators.bash import BashOperator
from airflow.providers.standard.operators.python import PythonOperator
from airflow.providers.standard.sensors.filesystem import FileSensor
from airflow.providers.standard.hooks.filesystem import FSHook


PROJECT_HOME = "/home/sari/telecom-etl"

READY_FILE = "usage.ready"

PASSWORD_FILE = (
    f"{PROJECT_HOME}/config/mysql.password"
)


def verify_ready_file():

    hook = FSHook(
        fs_conn_id="telecom_files"
    )

    base_path = hook.get_path()

    ready_path = os.path.join(
        base_path,
        READY_FILE
    )

    print("Filesystem path:", base_path)
    print("Checking file:", ready_path)

    if not os.path.isfile(ready_path):
        raise FileNotFoundError(
            f"Ready file not found: {ready_path}"
        )

    print("READY FILE FOUND")
    print("Telecom usage data is ready.")


with DAG(

    dag_id="telecom_customer_usage_etl",

    start_date=datetime(
        2026,
        9,
        1
    ),

    schedule="0 2 * * *",

    catchup=False,

    default_args={

        "owner": "data_engineering",

        "retries": 2,

        "retry_delay": timedelta(
            minutes=2
        ),
    },

    tags=[
        "telecom",
        "etl",
        "sqoop",
        "hdfs",
        "hive"
    ],

) as dag:


    wait_for_ready_file = FileSensor(

        task_id="wait_for_usage_ready_file",

        filepath=READY_FILE,

        fs_conn_id="telecom_files",

        poke_interval=30,

        timeout=30 * 60,

        mode="reschedule",
    )


    verify_file = PythonOperator(

        task_id="verify_file_using_hook",

        python_callable=verify_ready_file,

    )


    sqoop_extract = BashOperator(

        task_id="sqoop_extract_mysql_to_hdfs",

        bash_command=f"""

        echo "================================="
        echo "Starting Sqoop Extraction"
        echo "================================="

        hdfs dfs -rm -r -f \
        /telecom/raw/customer_usage

        sqoop import \\
        --connect jdbc:mysql://localhost:3306/telecom_db \\
        --username sqoop_user \\
        --password-file file://{PASSWORD_FILE} \\
        --table customer_usage \\
        --target-dir /telecom/raw/customer_usage \\
        --fields-terminated-by ',' \\
        --m 1

        echo "Sqoop extraction completed."

        echo "HDFS output:"

        hdfs dfs -ls \
        /telecom/raw/customer_usage

        """,
    )


    hive_transform = BashOperator(

        task_id="hive_transform_and_load",

        bash_command=f"""

        echo "================================="
        echo "Starting Hive Transformation"
        echo "================================="

        hive -f \
        {PROJECT_HOME}/scripts/telecom_transform.sql

        echo "Hive transformation completed."

        """,
    )


    usage_summary = BashOperator(

        task_id="generate_usage_summary",

        bash_command="""

        echo "================================="
        echo "Customer Usage Summary"
        echo "================================="

        hive -e "

        USE telecom_dw;

        SELECT
            customer_id,
            plan,
            total_call_minutes,
            total_sms,
            total_data_gb

        FROM customer_usage_summary

        ORDER BY total_data_gb DESC;

        "

        """,
    )


    pipeline_complete = BashOperator(

        task_id="pipeline_complete",

        bash_command="""

        echo "======================================"
        echo " TELECOM ETL PIPELINE COMPLETED"
        echo "======================================"

        """,
    )


    wait_for_ready_file \
        >> verify_file \
        >> sqoop_extract \
        >> hive_transform \
        >> usage_summary \
        >> pipeline_complete
```

# PART 50 — WHAT HAPPENS IF THE FILE DOES NOT ARRIVE?

Suppose:

```text
usage.ready
```

never arrives.

The Sensor:

```text
wait_for_usage_ready_file
```

keeps checking.

We configured:

```python
poke_interval=30
```

So it checks approximately every:

```text
30 seconds
```

We configured:

```python
timeout=30 * 60
```

So it waits for up to:

```text
30 minutes
```

Then it fails.

Most importantly:

```text
Sensor FAILED
      |
      X
    Sqoop
```

Sqoop does not start.

# PART 51 — WHAT HAPPENS IF SQOOP FAILS?

We configured:

```python
"retries": 2
```

and:

```python
"retry_delay": timedelta(minutes=2)
```

So:

```text
Sqoop
  |
FAIL
  |
Wait 2 minutes
  |
Retry 1
  |
FAIL
  |
Wait 2 minutes
  |
Retry 2
  |
SUCCESS / FAILED
```

If it finally fails:

```text
Sqoop FAILED
     |
     X
Hive
```

Downstream tasks don't proceed normally.

# PART 54 — WHY USE HDFS?

Answer:

> "HDFS provides the raw data storage layer. I keep the original extracted telecom data in HDFS before transformation so that the raw dataset can be retained and reprocessed if required."

---

# PART 55 — WHY USE HIVE?

Answer:

> "Hive provides a SQL interface for transforming and aggregating the HDFS data. In this project I use Hive to create the raw external table, fact table and customer usage summary."

---

# PART 56 — WHY USE SQOOP?

Answer:

> "The source data is in a relational MySQL database, while our Hadoop processing environment uses HDFS. Sqoop was designed to perform bulk transfer between relational databases and Hadoop, so it is used for the extraction stage."

---

# PART 57 — WHY USE A SENSOR?

Answer:

> "The telecom source system may finish at different times each day. Instead of starting Sqoop blindly, the FileSensor waits for the `usage.ready` file. Once the file appears, the extraction starts."

---

# PART 58 — WHY USE A HOOK?

Answer:

> "The Hook provides the programmatic interface to the external filesystem connection. My DAG uses FSHook to obtain the configured incoming directory and verify the ready file."

---

# PART 59 — SENSOR VS HOOK

Students often confuse these.

| Sensor                    | Hook                              
| Waits for something       | Communicates with 				external system |
| Checks condition          | Provides interface                

| Example: file exists      | Example: filesystem 				connection    |
| Controls workflow waiting | Helps access system               

| `FileSensor`              | `FSHook`                          

Simple memory:

```text
Sensor = WAIT

Hook = CONNECT
```
