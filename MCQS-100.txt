Q13. You have a 200MB file stored on HDFS with a default block size of 128MB and replication factor of 3. How many total blocks (physical copies) are stored across the cluster?
a) 1 block (128MB) + 1 block (72MB) = 2 logical blocks, replicated 3 times = 6 physical blocks.
b) 200MB / 128MB = 1.56 -> 2 logical blocks. Total replicas = 2 blocks  3 replicas = 6 physical blocks.
c) Only 2 physical blocks because the second block is too small to replicate.
d) 200MB / 128MB = 1.56 -> 2 logical blocks. Total replicas = 2 blocks  3 replicas = 6 physical blocks, plus the original = 7.

Answer: b) 200MB / 128MB = 1.56 -> 2 logical blocks. Total replicas = 2 blocks  3 replicas = 6 physical blocks.
Explanation: HDFS splits the file into logical blocks. Each block is replicated according to the replication factor. Two logical blocks  3 replicas each = 6 total physical block copies.

Q14. You are using the `hdfs dfs -put` command. The process fails because one of the three DataNodes that should receive a block replica has crashed. What happens?
a) The entire command fails and the file is not written.
b) The NameNode writes to the two healthy DataNodes and ignores the third replica requirement.
c) The pipeline is re-established with two healthy DataNodes, and the third replica is written to another DataNode. The command succeeds.
d) The command hangs indefinitely until the DataNode comes back online.

Answer: c) The pipeline is re-established with two healthy DataNodes, and the third replica is written to another DataNode. The command succeeds.
Explanation: HDFS data pipelining is fault-tolerant. If a DataNode fails during write, the pipeline closes, the block is sent to the remaining nodes, and the NameNode finds a new location for the missing replica.

Q15. Your organization uses a Hadoop cluster spread across two physical server racks (Rack A and Rack B). Rack awareness is enabled. A client on Rack A writes a new file with replication factor 3. Where will the replicas likely be placed?
a) All three replicas on any three random DataNodes in the cluster.
b) One replica on a DataNode in Rack A (same rack as client), and two replicas on a different DataNode in Rack B (different rack).
c) Two replicas on two different DataNodes in Rack A, and one replica on a DataNode in Rack B.
d) One replica on the client machine itself, and two replicas on any DataNodes.

Answer: b) One replica on a DataNode in Rack A (same rack as client), and two replicas on different DataNodes in Rack B (different rack).

Explanation:
HDFS uses a rack-aware replica placement policy to balance reliability and network efficiency:
First replica → placed on a DataNode in the same rack as the client (Rack A in this case). This reduces write latency since the client and DataNode are close.
Second replica → placed on a DataNode in a different rack (Rack B), ensuring fault tolerance in case an entire rack fails.
Third replica → placed on another DataNode in the same remote rack (Rack B), but on a different node than the second replica. This minimizes cross-rack traffic while still providing redundancy.
This strategy ensures:
Fault tolerance (data survives rack failure).
Load balancing (replicas spread across racks).
Reduced network overhead (only one cross-rack write).
So the placement is 1 replica in Rack A + 2 replicas in Rack B.

Q27. Your MapReduce job has 100 mappers and 10 reducers. You need to ensure that all records for the same user ID (the key) go to the same reducer. Which component guarantees this?
a) Input Split
b) Combiner
c) Partitioner (specifically `HashPartitioner` for user IDs)

Answer: c) Partitioner (specifically `HashPartitioner` for user IDs)
Explanation: The Partitioner determines which reducer receives a given (key, value) pair. The default `HashPartitioner` computes a hash of the key mod the number of reducers, ensuring same keys go to same reducer.

Explanation: `incrementColumnValue` is an atomic operation in HBase, specifically designed for counters. It reads the current value, increments it, and writes it back, all within a row lock.

Q47. You are performing a major compaction on an HBase table. What is the primary benefit of this operation?
