 # 15. Why `--fields-terminated-by ','`?

 This is important.

 Sqoop's default output delimiter isn't necessarily the same delimiter used by our Hive external table.

 We explicitly say:


--fields-terminated-by ','


 Therefore:


C001,John Carter,john.carter@...


 matches:


FIELDS TERMINATED BY ','


 in Hive.

 # 26. Transform RAW → Parquet


INSERT OVERWRITE TABLE orders_transformed
SELECT
    order_id,
    customer_id,
    CAST(amount AS DOUBLE),
    CAST(order_date AS DATE)
FROM orders_raw
WHERE order_id IS NOT NULL
  AND customer_id IS NOT NULL
  AND amount IS NOT NULL
  AND order_date IS NOT NULL;


 Now:


orders_raw
     |
     | CAST
     | validation
     v
orders_transformed
     |
     v
Parquet

 # 28. STEP 6 — Customer Order Summary

 Create warehouse table:


CREATE TABLE customer_order_summary (
    customer_id STRING,
    name STRING,
    total_spent DOUBLE,
    total_orders INT
)
STORED AS PARQUET;


 Transform:


INSERT OVERWRITE TABLE customer_order_summary
SELECT
    c.customer_id,
    c.name,
    SUM(o.amount) AS total_spent,
    COUNT(o.order_id) AS total_orders
FROM orders_transformed o
JOIN customers_raw c
    ON o.customer_id = c.customer_id
GROUP BY
    c.customer_id,
    c.name;


---

 # 35. Why Partitioning?

 Suppose you have:


5 TB orders


 and the business asks:


SELECT *
FROM orders_partitioned
WHERE order_date = '2026-01-14';


 Hive can avoid scanning unrelated date partitions.

 Conceptually:


orders_partitioned/

order_date=2026-01-05/
order_date=2026-01-06/
order_date=2026-01-07/
...
order_date=2026-01-14/


 Only the relevant partition needs to be read.

 # 42. Install Airflow

CONSTRAINT_URL="https://raw.githubusercontent.com/apache/airflow/constraints-${AIRFLOW_VERSION}/constraints-${PYTHON_VERSION}.txt"

    --constraint "${CONSTRAINT_URL}"

 For a current production installation, check the official Airflow installation page and select the version/constraint combination matching your Python version rather than blindly copying an old version number.  Apache Airflow

 # 45. Airflow DAG

 Create:

 Use:


from datetime import datetime

from airflow import DAG
from airflow.operators.bash import BashOperator

default_args = {
    "owner": "data-engineering",
    "depends_on_past": False,
}

with DAG(

 # 47. `02_transform.sql`


USE ecommerce_dw;

DROP TABLE IF EXISTS orders_transformed;

CREATE TABLE orders_transformed (
    order_id STRING,
    customer_id STRING,
    amount DOUBLE,
    order_date DATE
)
STORED AS PARQUET;

INSERT OVERWRITE TABLE orders_transformed
SELECT
    order_id,
    customer_id,
    CAST(amount AS DOUBLE),
    CAST(order_date AS DATE)
FROM orders_raw
WHERE order_id IS NOT NULL
  AND customer_id IS NOT NULL
  AND amount IS NOT NULL
  AND order_date IS NOT NULL;

 # 48. `03_customer_summary.sql`


USE ecommerce_dw;

DROP TABLE IF EXISTS customer_order_summary;

CREATE TABLE customer_order_summary (
    customer_id STRING,
    name STRING,
    total_spent DOUBLE,
    total_orders INT
)
STORED AS PARQUET;

INSERT OVERWRITE TABLE customer_order_summary
SELECT
    c.customer_id,
    c.name,
    SUM(o.amount),
    COUNT(o.order_id)
FROM orders_transformed o
JOIN customers_raw c
    ON o.customer_id = c.customer_id
GROUP BY
    c.customer_id,
    c.name;

 # 57. ETL vs ELT

 This distinction is important in interviews.

 | Area | ETL | This ELT Project |
| --- | --- | --- |
| Extract | Source | Source |
| Load | After transformation | Before transformation |
| Raw data | Often not retained | Retained |
| Transformation | PySpark/ETL engine | Hive |
| Data Lake | Optional | Core component |
| Transformation location | Before warehouse | Inside data platform |
| Flexibility | Lower | Higher |
| Reprocessing | May require source reload | Raw data retained |

 # 58. Your Interview Explanation

 You can say:

 > "I implemented an ELT-based e-commerce order analytics pipeline. Orders were received as CSV files and customer data came from MySQL. Orders were loaded directly into HDFS as the raw data lake layer, while customer data was ingested from MySQL into HDFS using Sqoop. Hive external tables were created on top of the raw HDFS data without modifying the source data. I then performed the transformation inside Hive by casting data types, validating records and joining orders with customer information. The transformed data was stored in Parquet tables. Finally, I created analytical datasets for customer revenue, daily sales trends and top customers. Airflow was used to orchestrate the end-to-end workflow."

---

 # 59. Interview Question: Why External Tables?

 Answer:

 > "I used external tables for the raw layer because the underlying HDFS files are owned by the data lake rather than Hive. Dropping the Hive table does not mean the raw source data should be deleted."

 Conceptually:


HDFS RAW
   |
   +---- Hive external table
   |
   +---- Other processing engines


 This makes the raw layer reusable.

---

 # 60. Interview Question: Why Parquet?

 Answer:

 > "The raw layer is stored as source-oriented text data, while the transformed warehouse layer uses Parquet because it is a columnar format and is better suited for analytical queries."

 So:


RAW
 ↓
CSV/Text

WAREHOUSE
 ↓
Parquet


---

 # 61. Interview Question: Why Keep RAW Data?

 Answer:

 > "Keeping raw data provides replayability and auditability. If the business logic changes, I can rerun the transformation against the original raw data without requesting the source system to resend the data."

 This is one of the strongest reasons for an ELT architecture.

---

 # 62. Interview Question: Where Does Transformation Happen?

 Answer:

 > "Transformation happens inside Hive after the data has already been loaded into HDFS. We convert the raw amount from STRING to DOUBLE, convert order_date to DATE, perform validation, join customer and order data, and aggregate the data into analytical Parquet tables."

---

 # 63. Interview Question: What Is Airflow Doing?

 Answer:

 > "Airflow is the orchestration layer. It doesn't replace Hive or Sqoop. It controls when each task runs, manages dependencies, provides task status and allows the pipeline to be scheduled and monitored."

 For example:


HDFS Load
    ↓
Sqoop
    ↓
Hive RAW
    ↓
Transformation
    ↓
Customer Summary
    ↓
Daily Sales


 Airflow manages these dependencies.

   |

 For a real enterprise pipeline, this is much more realistic than repeatedly performing full loads.
