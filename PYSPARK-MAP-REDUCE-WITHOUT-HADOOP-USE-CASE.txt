# 11. Create Spark Program

Create:


nano employee_salary.py
//
from pyspark import SparkConf, SparkCon

# Create Spark configuration
conf = SparkConf().setAppName("EmployeeSalaryAnalysis").setMaster("local[*]")

# Create SparkCon
sc = SparkCon(conf=conf)

# Read input file
lines = sc.File("input/employees.csv")

# Remove header
header = lines.first()

data = lines.filter(lambda line: line != header)

# MAP
# Convert each record into:
# (department, (salary, employee_count))

mapped = data.map(
    lambda line: (
        line.split(",")[2],
        (int(line.split(",")[3]), 1)
    )
)

# REDUCE
# Add salaries and employee counts department-wise

reduced = mapped.reduceByKey(
    lambda x, y: (
        x[0] + y[0],
        x[1] + y[1]
    )
)

# Calculate average salary

result = reduced.mapValues(
    lambda x: (
        x[1],
        x[0],
        x[0] / x[1]
    )
)

# Sort by department

sorted_result = result.sortByKey()

# Display result

for department, values in sorted_result.collect():
    employee_count = values[0]
    total_salary = values[1]
    average_salary = values[2]

    print(
        department,
        employee_count,
        total_salary,
        average_salary
    )

# Save output

output = sorted_result.map(
    lambda x: (
        x[0],
        x[1][0],
        x[1][1],
        x[1][2]
    )
)

output.map(lambda x: ",".join(map(str, x))) \
      .coalesce(1) \
      .saveAsFile("output/department_salary")

# Stop Spark

sc.stop()

The important operation is:

python

Before reduction, Spark groups records having the same key.

Conceptually:

(80000,1)

HR:
(45000,1)
(50000,1)

Finance:
(55000,1)

This grouping is the Shuffle stage.

# 21. Map, Shuffle and Reduce Identification

| Stage          | Spark operation    | Purpose                            

| Input          | `File()`       | Read CSV                           |
| Map            | `map()`            | Convert records to key-value pairs |
| Shuffle        | `reduceByKey()`    | Group same department keys         |
| Reduce         | `reduceByKey()`    | Aggregate salary and count         |
| Transformation | `mapValues()`      | Calculate average                  |
| Output         | `saveAsFile()` | Write local result                 |

Important point:

In Spark, `reduceByKey()` logically includes both the shuffle/grouping and reduction behavior. You don't write separate `shuffle()` and `reduce()` functions.

# 23. Why Use RDD Here?

RDD stands for:

Resilient Distributed Dataset

RDD is Spark's basic distributed data abstraction.

For learning MapReduce concepts, RDD is useful because operations such as:

python
map()
reduceByKey()
filter()
flatMap()


make the MapReduce logic easy to understand.

For example:

python
data.map(...)


is the Map-style transformation.

And:

python
data.reduceByKey(...)


performs key-based aggregation.

You can say:

> I implemented an Employee Department Salary Analysis project using Apache Spark RDDs. The input is a CSV file stored in the local filesystem. Spark reads the data using `File()`, removes the header, and uses `map()` to create department-based key-value pairs. `reduceByKey()` groups records by department and calculates total salary and employee count. Then `mapValues()` calculates the average salary. The final result is written to the local filesystem. The application runs in Spark local mode and does not use Hadoop, HDFS, or YARN.

# 26. One Important Difference From Hadoop MapReduce

// Hadoop MapReduce


Input
 ↓
Mapper
 ↓
Shuffle
 ↓
Reducer
 ↓
HDFS


// Spark RDD MapReduce-style processing


Local Input
 ↓
Spark RDD
 ↓
map()
 ↓
reduceByKey()
 ↓
Local Output


Spark keeps intermediate data in memory when possible, whereas traditional Hadoop MapReduce heavily relies on disk-based intermediate processing.
